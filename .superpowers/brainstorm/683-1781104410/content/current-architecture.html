六大架构问题

🔴 全局状态泛滥

global/ 包有 21+ 个包级变量，每个包直接读写。无法测试、无法追踪修改来源。

global.Config_p = config_p      // bootstrap
global.AgentRunner_p = runner    // bootstrap
global.SessionId = uuid.New()    // bootstrap
global.AgentMessage.Write  // session/summarizer

🟠 God Initializer

bootstrap/Initializer.go 387行，做所有事：文件IO、配置解析、Prompt模板、Agent创建、MCP设置、日志、TUI反馈。每个函数以全局变量为副作用。

func Init(an string) {
  getcwd()           // → global.CWD
  checkConfigFolder() // → global.ConfigFolderPath
  checkConfig()       // → global.HyperBotConfigPath
  configSystemPrompt() // → global.Systemprompt
  LoadConfig()        // → global.Config_p
  NewRunner()         // → global.AgentRunner_p
}

🟠 业务逻辑与TUI混杂

handler/ 和 session/ 直接调用 global.Print2AgentMessageView()，渲染代码遍布各层。换个UI框架等于重写一切。

🟡 无接口/无DI

所有依赖都是具体类型+全局变量。无法单测、无法mock。CLAUDE.md 明确指出: "No test files exist in this repository"

🟡 主循环脆弱

Bootstrap.go 的 for 循环手动管理6种状态转换，状态机隐含在 if/else 中，添加新状态需要修改多处。

🟡 初始化序列脆弱

Init() 的10个步骤严格有序但隐式依赖（例如 initMemorySessionService() 必须在 LoadConfig() 之后），顺序错误不会编译报错，只会在运行时panic。
